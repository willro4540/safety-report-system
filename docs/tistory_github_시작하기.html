GitHub 저장소 만들고 커밋·푸시하기 — 완전 처음부터

이 글은 컴퓨터에 아무것도 설치되어 있지 않은 상태에서 시작해서, GitHub 저장소를 만들고, 코드를 커밋(commit)하고, 푸시(push)까지 끝내는 전체 과정을 다룹니다. 프로그래밍을 전혀 몰라도 따라올 수 있게 썼습니다.

이 글을 다 따라 하면: 내 컴퓨터의 파일을 GitHub라는 공용 창고에 올려서, 언제 어디서든 꺼내 보고 다른 사람과 공유할 수 있게 됩니다.

0. 용어 사전 (처음 나올 때 한글 발음도 같이)

  • Git(깃) — 파일 변경 기록을 시간순으로 저장하는 프로그램
  • GitHub(깃허브) — 그 기록을 인터넷에 올려 공유하는 웹사이트
  • repository(레포지토리, 줄여서 "레포") — 프로젝트 하나를 담는 폴더+기록 전체
  • commit(커밋) — 지금 상태를 "여기까지 저장!"하고 스냅샷 남기기. 내 컴퓨터 안에서만 일어남
  • push(푸시) — 내 컴퓨터의 커밋들을 GitHub로 올려서 남들도 보게 하는 것
  • token(토큰) — 비밀번호 대신 쓰는, GitHub이 나를 인증할 때 쓰는 긴 문자열 암호
  • terminal(터미널) — 마우스 없이 글자로 컴퓨터에 명령을 내리는 화면
기억할 한 문장: 커밋 = 나만 저장, 푸시 = 그제서야 남들도 봄.

1. 준비물 설치

⚡ 원문 통짜 보기 (숙련자용, 설명 생략하고 바로 확인)

git --version
gh --version

1. 웹 브라우저에서 git-scm.com에 접속한다.

→ 자동으로 내 운영체제에 맞는 다운로드 버튼이 보인다.

2. 다운로드된 설치 파일을 실행하고, 기본값 그대로 "Next"만 눌러 설치를 끝낸다.

→ 설치 완료 메시지가 뜬다.

3. 터미널(Windows는 PowerShell)을 열고 아래를 입력한다:

git --version

→ git version 2.xx.x 처럼 버전 번호가 뜨면 설치 성공.

4. github.com에 접속해서 회원가입(Sign up)을 완료한다.

→ 로그인 상태로 GitHub 첫 화면이 보인다.

🔧 GitHub 로그인 정보를 터미널에 등록하기 (심화, 최초 1회만)

1. 아래를 입력한다 (따옴표 안은 본인 이름/이메일로 바꾼다):

git config --global user.name "내이름"
git config --global user.email "내이메일@example.com"

→ 아무 글자도 안 뜨면 정상(성공했다는 뜻).

이 정보는 앞으로 내가 만드는 모든 커밋에 "누가 만들었는지" 표시로 남는다. 딱 한 번만 설정해두면 다시 안 해도 된다.

2. 로컬(내 컴퓨터)에서 프로젝트 시작하기

⚡ 원문 통짜 보기

mkdir my-project
cd my-project
git init

1. 프로젝트를 담을 새 폴더를 만든다:

mkdir my-project

→ 아무 글자도 안 뜨면 정상(폴더가 생겼다는 뜻).

2. 그 폴더 안으로 들어간다:

cd my-project

→ 프롬프트 경로가 my-project로 바뀐다.

3. 이 폴더를 Git이 관리하도록 초기화한다:

git init

→ Initialized empty Git repository... 메시지가 뜬다.

4. 원하는 파일(코드, 문서 등)을 이 폴더 안에 넣는다 (탐색기로 복사해도 되고, 새로 만들어도 됨).

→ 탐색기에서 폴더를 열어보면 방금 넣은 파일이 보인다.

3. GitHub에 저장소(창고) 만들기

1. github.com에 로그인한 상태에서 오른쪽 위 "+" 버튼을 누르고 "New repository"를 클릭한다.

→ 새 저장소 만들기 화면이 뜬다.

2. Repository name에 저장소 이름(예: my-project)을 입력한다.

→ 이름 옆에 초록색 체크가 뜨면 사용 가능한 이름이다.

3. Public(누구나 볼 수 있음) / Private(나만 봄) 중 하나를 선택한다.

→ 선택한 쪽에 동그라미가 채워진다.

4. 다른 옵션(README 추가 등)은 전부 체크 해제한 채로 "Create repository"를 누른다.

→ 텅 빈 저장소 페이지와 함께, 연결 방법을 알려주는 안내 화면이 뜬다.

이 안내 화면에 뜨는 https://github.com/내계정/my-project.git 같은 주소를 복사해두면 다음 단계에서 그대로 쓴다.

4. 커밋하고 GitHub로 푸시하기

⚡ 원문 통짜 보기 (숙련자용, 절차 생략하고 바로 치기)

git add .
git commit -m "첫 커밋"
git remote add origin https://github.com/내계정/my-project.git
git branch -M main
git push -u origin main

1. 방금 넣은 파일들을 장바구니(스테이징)에 담는다:

git add .

→ 아무 글자도 안 뜨면 정상.

2. 담은 내용으로 스냅샷(커밋)을 찍는다:

git commit -m "첫 커밋"

→ 1 file changed, ... 같은 요약 줄이 뜬다.

3. 아까 복사해둔 GitHub 주소를 내 컴퓨터의 저장소와 연결한다:

git remote add origin https://github.com/내계정/my-project.git

→ 아무 글자도 안 뜨면 정상.

4. 기본 브랜치 이름을 main으로 맞춘다:

git branch -M main

→ 아무 글자도 안 뜨면 정상.

5. GitHub로 실제로 올린다:

git push -u origin main

→ 진행률(%) 표시 후 main -> main 같은 완료 메시지가 뜬다.

6. 브라우저에서 GitHub 저장소 페이지를 새로고침한다.

→ 방금 커밋한 파일들이 웹페이지에 그대로 보인다. 성공!

🔧 push할 때 로그인을 요구하면? (심화, 인증 토큰 발급)

2021년 이후 GitHub은 비밀번호 로그인을 막고 토큰(token) 을 대신 쓰게 한다. push 시 아이디/비밀번호를 물어보면, 비밀번호 자리에 토큰을 넣는다.

1. GitHub 우측 상단 프로필 사진 클릭 → Settings로 들어간다.

→ 설정 페이지가 뜬다.

2. 왼쪽 메뉴 맨 아래 Developer settings → Personal access tokens → Tokens (classic) → Generate new token을 클릭한다.

→ 토큰 생성 화면이 뜬다.

3. 권한(scope)에서 repo를 체크하고, 화면 맨 아래 Generate token을 누른다.

→ ghp_로 시작하는 긴 문자열이 딱 한 번 화면에 표시된다.

4. 이 문자열을 안전한 곳에 복사해둔다 (다시는 안 보여줌).

→ 창을 닫으면 다시 볼 수 없으니 반드시 저장.

5. push 시 비밀번호를 물어보면, 이 토큰 문자열을 그대로 붙여넣는다.

→ push가 정상적으로 완료된다.

5. ⚠️ 위험한 명령어 — 반드시 조심할 것

아래 명령어들은 한 번 실행하면 되돌리기 어렵거나, 남의 작업을 지울 수 있는 명령어입니다. 처음엔 특히 조심하세요.
  • git push --force (포스 푸시) — GitHub의 기록을 강제로 덮어씀. 팀원이 이미 올린 커밋이 통째로 사라질 수 있음. 혼자 쓰는 브랜치, 아무도 안 받아간 상태에서만 비교적 안전.
  • git reset --hard (리셋 하드) — 아직 저장(커밋) 안 한 내 작업을 전부 버림. 복구 거의 불가능. 실행 전 반드시 git status로 확인하고, 필요하면 git stash로 먼저 빼둘 것.
  • git branch -D (대문자, 강제 삭제) — 아직 합쳐지지 않은 작업까지 강제로 지움. 소문자 -d는 이미 합쳐진 것만 안전하게 지워줌.
  • .git 폴더 직접 삭제 — 지금까지 쌓인 모든 버전 기록이 통째로 사라짐(파일은 남아도 기록은 복구 불가).

공통 원칙: 이미 GitHub에 올라가서 남이 봤을 수도 있는 것을 건드리는 명령어는 항상 조심하고, 아직 내 컴퓨터에만 있는 것을 건드리는 건 상대적으로 안전합니다 (그래도 git stash로 백업해두는 습관을 들이면 더 안전합니다).

커밋 = 나만 저장, 푸시 = 그제서야 남들도 봄 — 이 한 문장만 기억하면 나머지는 손이 기억합니다.

※ 이 글의 명령어는 Windows PowerShell 기준이며, Mac/Linux 터미널에서도 Git 명령어 자체는 동일하게 동작합니다.
